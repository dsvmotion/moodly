# Fase 0 — Fontanería PWA: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** que `apps/web` se pueda instalar en el iPhone (Safari → "Añadir a pantalla de inicio"), se abra a pantalla completa y muestre una página offline limpia, sin cachear nunca datos de tenant ni de sesión.

**Architecture:** manifest como ruta de Next (`src/app/manifest.ts`), service worker clásico escrito a mano en `public/sw.js` con la decisión de caché como función pura `pickStrategy` (fuente única, testeada leyendo el archivo), registro en cliente con la lógica en `src/lib/pwa/register.ts` y un aviso de versión nueva. Los assets PWA se sacan del matcher del proxy para que lleguen sin sesión.

**Tech Stack:** Next.js 16.3.6 (App Router, Metadata API), next-intl 4, Vitest, Playwright 1.63, ImageMagick (`convert`, solo para generar los PNG una vez).

**Spec:** `docs/superpowers/specs/2026-10-18-pwa-fase0-design.md` (incluida la §14, adenda del plan).

## Global Constraints

- **Ninguna dependencia nueva**: no se toca ningún `package.json` ni el lockfile.
- Nombre de caché: `moodly-shell-v1`. Solo se cachean assets públicos de build y la página offline; **nunca** una navegación, una petición que no sea GET ni una de otro origen.
- Manifest: `start_url: "/app"`, `scope: "/"`, `display: "standalone"`, `orientation: "portrait"`, `lang: "es"`, `background_color` y `theme_color` `#f4f4f5`.
- Nombre de la marca siempre con `BRAND_NAME` de `@repo/config` en código TS/TSX.
- El SW solo se registra con `process.env.NODE_ENV === "production"`.
- Todo texto visible de la app va en `apps/web/messages/es.json` y `en.json`.
- Zonas sensibles que toca este plan: `apps/web/src/proxy.ts`, `apps/web/next.config.ts`, `AGENTS.md`, `CLAUDE.md`. El PR necesita `revisado-humano` y **no lo mergea el agente**.
- Commits con el pie de atribución de la sesión.

## Review Focus

1. **Usuario sin sesión en `/login`** (donde se instala la app): debe recibir manifest, iconos y `sw.js` con 200, nunca una redirección → Task 1 (unit del matcher) y Task 6 (e2e con `maxRedirects: 0`).
2. **Dispositivo compartido**: tras navegar con sesión, en Cache Storage no puede quedar ninguna página `/app…` ni `/login` → Task 6 (e2e que lista las cachés).
3. **Server Actions con el SW activo** (login, logout, aprobar): deben seguir funcionando → Task 4 (POST = passthrough) y la suite e2e existente, que corre contra el build de producción con el SW registrado (Task 6, paso de regresión).
4. **Despliegue con la app abierta**: ni cambio silencioso ni aviso en la primera instalación → Task 5 (tests de `registerServiceWorker`).
5. **Abrir la app instalada sin conexión**: página offline, no el error de Safari → Task 6 (e2e offline).

**Files:**

- Test: `apps/web/src/lib/pwa/sw.test.ts`

**Interfaces:**
- Produces: en `public/sw.js`, la función pura de nivel superior
  `pickStrategy(request: { method: string; url: string; mode: string }, origin: string): "passthrough" | "cache-first" | "network-first"`;
  `const CACHE = "moodly-shell-v1"`; respuesta al mensaje `{ type: "SKIP_WAITING" }` con `self.skipWaiting()` (lo usa la Task 5).

```ts
  r: { method: string; url: string; mode: string }, origin: string) => string;

```

Casos (`it.each` con nombre legible):
  - `passthrough`: `POST /app/approvals` (navigate), `POST /login`, `GET https://xyz.supabase.co/rest/v1/organizations`, `GET /login` (navigate), `GET /login?next=%2Fapp`, `GET /auth/callback`, `GET /api/anything`.
  - `network-first`: `GET /app` (navigate), `GET /app/settings/organization` (navigate), `GET /` (navigate).
  - `cache-first`: `GET /_next/static/chunks/main.js`, `GET /_next/static/media/font.woff2`, `GET /icons/icon-192.png`, `GET /manifest.webmanifest`, `GET /offline.html`.
  - Y un test de que `offline.html` contiene `Sin conexión` y no contiene `<script`.

- [ ] **Step 2: Run** `pnpm --filter @repo/web exec vitest run src/lib/pwa/sw.test.ts` — Expected: FAIL (no existe `sw.js`).

- [ ] **Step 3: Implement `public/sw.js`** (script clásico, sin `import`/`export`):
  - `pickStrategy` aplica las reglas de la spec §7 en este orden: método ≠ GET → `passthrough`; origen ≠ `origin` → `passthrough`; ruta `/login`, `/login/…` o `/auth/…` → `passthrough`; `/_next/static/…`, `/icons/…`, `/manifest.webmanifest`, `/offline.html` → `cache-first`; `mode === "navigate"` → `network-first`; resto → `passthrough`.
  - Todo el cableado (`install`, `activate`, `message`, `fetch`) dentro de `if (typeof self !== "undefined" && self.addEventListener) { … }`.
  - `install`: `caches.open(CACHE)` → `addAll(["/offline.html", "/manifest.webmanifest", "/icons/icon-192.png", "/icons/icon-512.png", "/icons/apple-touch-icon.png"])`. Sin `skipWaiting`.
  - `activate`: borra cachés con nombre ≠ `CACHE`; `self.clients.claim()`.
  - `fetch`: `passthrough` → no llama a `respondWith`. `cache-first` → responde con la caché si hay y en paralelo refresca (`fetch` + `put` solo si `response.ok && response.type === "basic"`); si no hay, red + `put` con la misma condición. `network-first` → `fetch(event.request)`; si lanza, `caches.match("/offline.html")`. **La respuesta de navegación nunca se guarda.**
  - Lint: si `pnpm --filter @repo/web lint` marca `self`, `caches` o `clients` como no definidos, decláralos en un comentario `/* global … */` en la cabecera, solo los que marque.

- [ ] **Step 4: Implement `public/offline.html`**: HTML autónomo, `lang="es"`, `<title>Sin conexión</title>`, viewport `width=device-width, initial-scale=1, viewport-fit=cover`, estilos inline sin recursos externos: fondo `#f4f4f5` y texto `#000000`; con `prefers-color-scheme: dark`, fondo `#0b0b0c` y texto `#f4f4f5`. Fuente del sistema. Contenido: `<h1>Sin conexión</h1>` y `<p>Vuelve a intentarlo cuando tengas internet.</p>`, centrados. Sin `<script>`.
